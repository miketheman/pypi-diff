# pypi-diff

A browser-based tool for comparing two PyPI packages at a glance — identifying what files differ, what's been added/removed, and drilling into individual file diffs on demand. Primary use case: investigating reports of package impersonation ("X is copying Y") and comparing versions of the same package.

## Architecture

**Static client-side app, native ES modules, no build step.** All diff logic runs in the browser. `js/compare.js`, `js/diff.js`, `js/tar.js`, `js/net.js` and `js/util.js` touch no DOM at import time, so the tests import them directly. PyPI's `files.pythonhosted.org` has CORS configured to allow browser-initiated Range requests (OPTIONS preflight returns 204 with `Access-Control-Allow-Headers: Range, Accept-Encoding`), so the app talks directly to PyPI infrastructure. The app must be served over HTTP (not `file://`) because browsers treat `file:` origins as `null` and block CORS requests.

`serve.py` is optional. It's a static file server plus a CORS proxy at `/proxy/files.pythonhosted.org/*` — useful as a fallback if PyPI's CORS configuration regresses. On the first file request from a localhost origin, the frontend probes that endpoint and routes through the proxy if it's detected (by the `X-PyPI-Diff-Proxy` response header that `serve.py` sets). Any static HTTP server works (e.g., `python -m http.server`); the proxy just isn't active in that case.

### How it works

1. User enters two package names (can be different packages or same package, different versions). A `files.pythonhosted.org` file URL works in place of a name, for quarantined projects whose JSON API returns 404
2. Fetches metadata from `https://pypi.org/pypi/{package}/json` (has CORS)
3. User selects version + specific file (wheel or sdist) from dropdowns on each side
4. **For wheels (.whl = ZIP files):** Uses HTTP Range requests to read only the ZIP central directory (~16-64KB) regardless of package size. File listings appear instantly even for 100MB+ wheels. Individual file contents are fetched on-demand via additional range requests when user clicks to diff.
5. **For sdists (.tar.gz):** Full download required (gzip compression prevents partial reads). Shows progress bar. Uses native Compression Streams API for gzip decompression, custom tar parser for file listing.
6. Displays summary (similarity %, counts by status) and filterable file table
6a. While a comparison runs, the form is `inert` and Compare is disabled. The refine functions use the names and versions captured at the click
7. Click any file row → fetches content (range request for wheels, already in memory for sdists) → renders line diff in modal

### Key technical details

**ZIP central directory via range requests (the core trick):**
- ZIP archives store their table of contents (central directory) at the END of the file
- 1-byte range GET (`bytes=0-0`) → total size from `Content-Range`. Not HEAD: `files.pythonhosted.org` sends no `Access-Control-Allow-Origin` on HEAD responses, so a cross-origin HEAD always fails
- Range request for last ~64KB → find End of Central Directory record (signature `PK\x05\x06`, scan backwards)
- Parse EOCD to get central directory offset/size/entry count
- If CD wasn't in the initial 64KB fetch, do one more range request for it
- Parse each CD entry (signature `PK\x01\x02`) for filenames, sizes, CRC32, compression method, local header offsets
- To fetch individual file content: single range request for local header + compressed data (estimates header size from central directory, falls back to second request if extra fields overflow). Decompresses with native `DecompressionStream('deflate-raw')`.
- Reference: Simon Willison's implementation at https://github.com/simonw/research/tree/main/http-range-wheel-metadata

**Path normalization (wheel-aware):**
- **Wheels:** `.dist-info` and `.data` directories have `name-version` prefix stripped (e.g. `pkg-1.0.dist-info/METADATA` → `.dist-info/METADATA`). The primary code directory (named after the distribution, else the one with the most files) has its name stripped; other top-level directories keep their full path.
- **Sdists:** Strips the wrapping `name-version/` directory (first component).
- **Both:** `.egg-info` directories that are the first path component after the steps above have the package-name prefix stripped (e.g. `django_environ.egg-info/SOURCES.txt` → `.egg-info/SOURCES.txt`). Strips leading `./`, normalizes path separators, filters directory-only entries.

**Comparison strategy:**
- First pass: Set operations on normalized paths → added/removed/common files
- For common files in wheels: compare CRC32 + uncompressed size from ZIP headers (instant, no content fetch needed). Both values come from the uploader and a CRC-32 can be forged, so "identical" for a wheel means the headers match, not that the bytes were read
- For common files in sdists: byte-by-byte comparison (already in memory from full download)
- **Equivalence detection:** For files marked modified, fetches content and normalizes package name/version/whitespace differences. Names inside URLs are not normalized. If normalized content matches, file is marked "equivalent" rather than "modified". Special handling for RECORD files (compares only normalized file path list, ignoring hashes/sizes).
- **Move detection:** Matches added/removed files by basename + content identity (CRC32 for wheels, byte comparison for sdists). Uses path suffix scoring to prefer structurally similar matches (e.g. `a/b/c.py` matches `x/a/b/c.py` over `y/z/c.py`). Empty files are never matched. A move is one row at the new path, with `movedFrom` set.
- Content diffing is lazy — only computed when user clicks a specific file
- **Word-level changes:** where a removed block is followed by an added block, `pairLines` in `js/diff.js` pairs lines by token similarity (Dice coefficient, at least 0.5, order-preserving), and each pair gets a `diffWordsWithSpace` diff. Indentation is compared separately, so re-indenting marks only the extra indent. Lines over 500 characters and blocks over 10,000 line pairs get no word diff
- Line ending normalization (CRLF→LF) applied before diffing
- Binary detection: scan first 8KB for null bytes
- A diff that takes over 5 seconds (files with little in common) falls back to one removed block and one added block

**File statuses (canonical order):** Modified → Added → Removed → Moved → Equivalent → Identical. This order is consistent across summary bar, filter tabs, and help popover. The table sorts by path.

**Only `.whl` and `.tar.gz` are supported, and both sides must be the same type.** Anything else shows an error.

**Request optimization:**
- `fetchZipFileContent` combines header + data into a single range request (estimates header size from central directory entry, falls back to second request only if extra fields overflow)
- `refineWheelComparison` runs in batches of 4 to respect browser connection limits (~6 per domain)
- Size-delta filter skips refinement for files where the size difference exceeds what name/version substitution could explain (`(nameDelta + verDelta) * 200 + 64` bytes), and for files whose compressed or uncompressed size is 1 MB or more
- Maximum 50 files refined per comparison

### CORS

Both `pypi.org` and `files.pythonhosted.org` have CORS configured:
- `pypi.org` — `Access-Control-Allow-Origin: *` on all JSON API responses
- `files.pythonhosted.org` — OPTIONS preflight returns 204 with `Access-Control-Allow-Headers: Range, Accept-Encoding` and `Access-Control-Max-Age: 86400`

If CORS fails in the future (e.g., CDN config change), errors will appear in the browser console. Requests go directly to PyPI infrastructure unless the page is served by `serve.py`, in which case file requests route through its proxy.

## Untrusted input

Archive contents come from packages that may be malicious.

- Paths and file content reach the DOM through `textContent` and `<template>` only. Do not use `innerHTML` for them.
- Duplicate archive entries each keep a row (`[duplicate entry N]`). N counts up until the label is unused, so a file named like a label cannot replace a row.
- The parsers must list what Python's `zipfile` and `tarfile` would extract. Where they do not model a construct they throw: ZIP64 records and extra fields, a ZIP directory whose offset, size or entry count disagree, Unicode-path extra fields, sparse tar entries, base-256 or signed tar sizes, stacked or global pax headers that rename entries, bad tar checksums. Tar hard links and symlinks are listed as rows whose content names the target. Add a test in `tests/archive.test.js` for any new construct.
- Package-name normalization skips a name inside a URL or inside a longer name (`pkg-core`, `types_pkg`), so a squat that depends on a second squat stays "modified".
- Control and format characters (Unicode categories Cc and Cf, which cover bidi and zero-width characters), line and paragraph separators and the Hangul fillers render as `U+XXXX` markers (`hiddenCharSegments`), in the table, the diff and the dialog title.
- Decompression stops at 50 MB per wheel file and 500 MB per sdist. `decompress` feeds the input in 16 KB awaited slices: browsers inflate a whole written chunk before the reader runs, so one large write would defeat the limit. Node behaves differently, so the node test does not prove the browser behavior. Stored (uncompressed) wheel entries over 50 MB are refused too.
- A file with a null byte in its first 8 KB is treated as binary; the dialog offers "Show as text anyway".

## GitHub Pages

The app is built to be served as a static project site (`https://<user>.github.io/pypi-diff/`):

- Every URL in `index.html`, the CSS and the modules is relative, so the app works under a subpath. Keep it that way.
- Nothing is loaded from a script CDN. jsdiff is vendored, so the CSP allows scripts from `'self'` only.
- The CSP is a `<meta>` tag because Pages cannot set response headers. It has no `'unsafe-inline'`: no inline `style=""` attributes, no inline event handlers, and the single inline script (theme, before first paint) is allowed by its sha256 hash. Changing that script means updating the hash in the same tag.
- The proxy probe only runs on localhost, so a deployed site never requests `/proxy/`.
- `.github/workflows/pages.yml` publishes only `index.html`, `favicon.svg`, `.nojekyll`, `css/`, `js/` and `vendor/`. A new top-level app file must be added to its `cp` line (and to `serve.py`'s allowlist). In the repo settings, Pages source must be "GitHub Actions".
- Workflows reference actions by exact tag (`actions/checkout@v7.0.1`), and `.github/workflows/actions.lock` pins each tag to a commit. After adding a workflow or changing any `uses:`, run `gh actions-lock` and commit the lockfile, or `verify-lockfile.yml` fails. Dependabot updates the workflow and the lockfile together.
- Shareable state is in the query string, which Pages serves without any rewrite rules.

## Dependencies

- **jsdiff 9.0.0** (vendored in `vendor/`) — Myers diff algorithm (same as git). `diffLines()` for the file diff, `diffWordsWithSpace()` for changes inside a line. The build is a UMD script; `js/diff.js` imports it for its side effect of defining `globalThis.Diff`, which works in the module worker and in node
- **Compression Streams API** (native browser) — gzip decompression for sdists, deflate-raw for individual ZIP entries. Replaced pako.

No build step. No npm install. No bundler.

## URL Parameters (shareable)

`?a=requests&va=2.31.0&fa=requests-2.31.0-py3-none-any.whl&b=reqeusts&vb=0.1.0&fb=reqeusts-0.1.0-py3-none-any.whl&tab=modified&file=__init__.py`

- `a`, `b` — package names, or a `files.pythonhosted.org` file URL
- `va`, `vb` — versions
- `fa`, `fb` — distribution filenames (stable across API ordering changes)
- `tab` — active filter tab (omitted when "all")
- `file` — auto-open a specific file diff

## Known Limitations / TODO

### Not yet implemented
- **Byte-checking "identical" wheel files** — a same-length file with a forged CRC-32 shows as identical and is never fetched. Fixing it means downloading content for identical rows, within some budget, and labeling the unchecked ones.
- **Lenient decompression** — Python accepts gzip with trailing bytes or several members, and ZIP entries with padding. `DecompressionStream` rejects them, so such archives show an error here.
- **ZIP64 support** — Archives >4GB or with >65535 entries use ZIP64 extended records (`PK\x06\x06`/`PK\x06\x07`). Currently throws an error whenever a ZIP64 locator, sentinel field or extra field is present. Need to detect `0xFFFFFFFF` sentinel values in EOCD fields and parse the ZIP64 EOCD locator + record with 8-byte offsets.
- **IndexedDB caching** — Repeated comparisons re-download everything. Could cache ZIP central directories and extracted file contents.
- **RECORD file comparison** — Wheels contain a `RECORD` file with SHA256 hashes of every file. Could use this for instant content-identical detection without fetching file data.
- **Metadata-focused summary** — For impersonation analysis, auto-extract and compare key metadata: `setup.py`/`setup.cfg`/`pyproject.toml` install_requires, entry_points, scripts. Highlight any post-install hooks or unexpected executables.
- **Virtual scrolling for the file table** — Packages with thousands of files (e.g., tensorflow) render a huge table. Do not use `content-visibility` on diff lines: it clips long lines, so text padded far to the right cannot be scrolled to.

### Design decisions
- Light theme (PyPI-inspired) with Source Sans 3 / Source Code Pro typography; dark mode toggle (system/light/dark, persisted to localStorage)
- Uses PyPI's actual brand colors (#006dad blue, #ffd343 yellow, #148024 green, #d52d40 red)
- Dark diff modal (diffs read better on dark backgrounds) with blue header bar
- Status badges: Modified (yellow), Added (green), Removed (red), Moved (blue), Equivalent (purple), Identical (grey)
- Similarity ring percentage (counts identical + equivalent + moved), rounded down so only a full match reads 100%
- Native `<dialog>` for file diffs with minimap sidebar showing hunk positions
- Help legend is a native `popover`, anchored to its button with CSS anchor positioning where supported
- Theme uses `light-dark()` colors driven by `<meta name="color-scheme">`
- Filter tabs with URL persistence
- Per-file similarity % column (size-based approximation for modified files)
- Package name links to pypi.org project page

## Running

```bash
python -m http.server        # http://127.0.0.1:8000 (static only)
python serve.py              # http://127.0.0.1:8000 (static + CORS proxy)
```

`serve.py` serves only `index.html`, `favicon.svg`, `js/`, `css/` and `vendor/`. Add a new top-level file or directory to `STATIC_FILES` / `STATIC_DIRS` or it returns 404.

Any HTTP server works. `file://` URLs won't work (browsers treat them as `null` origin, blocking CORS).

## Tests

```bash
node --test          # or: npm test
```

Covers the pure modules: path normalization, comparison, move and equivalence detection, tar parsing, line pairing and word diffs, file-URL metadata, the decompression limit and hidden-character detection. UI code in `js/main.js` has no automated tests; check it in a browser.

## Testing suggestions

Good test cases for development:
- **Same package, adjacent versions:** `requests` 2.31.0 vs 2.32.0 (small diff, mostly identical)
- **Impersonation scenario:** `graphifyy` 0.3.11 vs `graphifyyy` 0.3.11 (typosquat — tests equivalence detection)
- **Large wheel with .data dirs:** `arcgis` 2.4.2 vs `arcgis-py-works-with3-14` 0.1 (tests move detection across `.data/platlib/` restructuring)
- **Different packages, same ecosystem:** `ariadne` 0.18.0 vs `zepben-ariadne-codegen` 0.18.0.1 (tests that genuinely different files with common basenames like `utils.py` aren't falsely marked as moved)
- **Large wheel:** `numpy` or `tensorflow` (tests range request performance on big files)
- **Pure Python wheel:** `six` or `pip` (small, simple, good for verifying basic flow)
- **Sdist comparison:** `flask` sdists across versions (tests tar.gz download + parse path)
